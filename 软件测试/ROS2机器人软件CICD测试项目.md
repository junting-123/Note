## ROS2机器人"电量不足自动回家"功能CI/CD测试项目

### 项目背景

> 开发并维护一套完整的 **CI/CD 自动化流水线**，实现从代码推送到构建、测试、部署的全流程自动化。ROS2 机器人节点与测试程序均通过 **Docker** 容器化运行于**虚拟机**，确保各环节环境一致性并提升交付效率。由于没有真实机器人硬件，所有测试均在 Gazebo 仿真环境中完成。



- **全流程容器化**：使用 **Docker** 将 ROS2 机器人节点（含 Gazebo 仿真环境）打包为镜像，部署至虚拟机；接口测试（Topic/Service 通信测试）与性能测试脚本同样运行在 Docker 容器中，实现测试环境与生产环境的高度一致；
- **Dify测试用例自动生成：基于 **Dify** 搭建 LLM 工作流，输入 ROS2 节点功能描述（如"电量低于15%时发布回家坐标"），自动生成 Pytest 格式的接口测试用例代码；覆盖功能测试、边界值测试、异常容错测试、时序响应测试等多个维度，测试用例编写效率提升 70%；
- **接口自动化测试**：基于 **Pytest + launch_testing + Allure** 搭建 ROS2 接口自动化测试框架，覆盖 Topic 消息发布订阅、Service 服务调用等核心通信接口，验证机器人电量判断与回家决策逻辑的正确性，生成可视化 Allure 测试报告；
- **性能与稳定性测试**：引入 **JMeter** 进行性能与稳定性测试，模拟多节点高并发消息场景，验证 ROS2 节点在高负载下的消息处理能力与响应延迟，确保服务可靠性；
- **CI/CD 流水线**：基于 **Jenkins** 搭建自动化流水线，结合 **Git Webhook** 实现代码推送自动触发构建、测试与部署；实现**路径级精准触发**，不同目录变更自动匹配并执行对应测试任务（如修改电量决策模块仅触发对应测试套件）；
- **实时通知**：集成**飞书机器人**，实时推送构建、测试与部署结果，包括测试通过率、失败用例详情及性能指标告警，实现问题快速响应。



### 项目成果

- 基于 **Dify** 搭建 AI 测试用例生成工作流，输入自然语言需求描述，自动输出 Pytest 格式测试代码，**测试用例编写效率提升 70%**，人工介入从每用例 5 分钟降至 1.5 分钟；
- 实现 **全流程自动化**，代码推送后自动触发测试，单次流水线执行时间控制在 15 分钟内，问题发现平均提前至 PR 合并阶段；
- 通过 **JMeter** 验证节点在高并发（100 条/秒）场景下 CPU 使用率 < 50%，消息处理延迟 < 100ms，2 小时稳定性测试内存增长 < 10%；
- 通过 **路径级精准触发**，避免无关代码变更触发不必要的测试任务，CI 资源消耗降低约 40%；
- 累计发现并拦截 **4 类典型缺陷**（电量阈值判断错误、临界值状态震荡、响应延迟超标、电池话题断连节点崩溃），有效保障了机器人决策模块的交付质量。
